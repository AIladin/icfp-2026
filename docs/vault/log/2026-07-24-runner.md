## 16:20 — why a runner

Up to now the only way to find out whether a program worked was to submit it and read `passed N/M`.
No ticks, no trace, no idea which case broke or where the man died — and a [[Pipe drawing traps|load
error]] burns the round-trip to tell us nothing but a string. So: a local implementation of the
machine, faithful to [[language-reference]]. Written up as [[Local runner]], code in
`py/libs/runner/` (import `littleman`, script `lm`).

Scope call: **no [[LM-75 Display]]**. A `:` or `=` in the source is a named load error and a
[[Display assignments|frame-judged]] case is reported *skipped*, never passed — a silently ignored
display would make `palette` and `plotter` look solved.

## 16:35 — the two bugs that mattered

Both were the same mistake, that **a character's meaning comes from where it sits**:

1. `+` is addition inside a room, so `_find_rooms` had to skip any `+` inside an already-accepted
   room — otherwise a `+--+` written as code parses as a nested room.
2. `v` is a turn inside a room, so a `v` one cell below the top wall read as a pipe leaving that
   wall. Pipe candidates now skip every cell in a room.

Neither showed up in a hand-written example; both showed up the moment a test used a loop with a
turn in it. Recorded because the same trap will hit any program *generator* we write.

## 16:45 — verification against the server

Wrote a deliberately different `triangle` solution from the one in
[[2026-07-24-triangle|the triangle log]] — 31×3, two rooms, `n(n+1)` in one and the halving in the
other — precisely so it exercised a different code path. Runner: 6/6 public, 11 ticks.
**Server: 19/19.**

Then ran the 9×9 folded layout from [[Single-variable closed form]], which had been written but never
verified or submitted. Runner: 6/6, **13 ticks, score 81 × 13 = 1053** — matching the projection in
that log exactly. Submitted: **19/19** as well.

So the runner agrees with the server on 13 private cases it never saw, from two structurally
different programs. That covers [[Numeric literals|literals]], blocking receives, pipe latency,
[[Park and swap]], `* + / }`, turns, and the output-pipe drain after `H`.

`triangle` now stands at 19/19 with footprint 81 — first graded problem banked.

## 16:55 — what is still assumed

Five places where the spec does not actually say what happens; each is implemented one way and
tagged, so nobody has to re-derive them at 4am:

- [[U turns toward the pipe flow]] — worth settling before the first merge of two producers, since a
  wrong turn is a wall error rather than a wrong answer
- [[Backtick pairing is sequential per axis]] — the permissive direction, which is the dangerous one
- `V` is not a pipe arrowhead; a digit inside a literal is a nop; a `wall` error is any step off room
  interior

## Next

1. `memory`, `reverse-a-list`, `sort-numbers` — all need [[Rounds|multi-round]] state, which the
   runner already gates correctly. Those will be the first real users of `--trace`.
2. `S`, `R`, `U`, `q` and multi-room concurrency are implemented but unexercised. The first program
   that uses them should be stepped in the editor once and compared against the trace.
3. Displays, when a display problem is worth the points.
