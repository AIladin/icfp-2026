## 17:05 — closing the display hole

[[Local runner]] shipped with one deliberate gap: `:` or `=` anywhere in a program was a named load
error, and a [[Display assignments|frame-judged]] case came back *skipped*. That was the right call
at 16:20 and the wrong one by 17:00, because it puts two problems out of reach — `palette` (practice,
8×8) and **`plotter`** (graded, 32×24, one Bresenham segment per round). `plotter` is 2 points we
could not even attempt.

Design call: an [[LM-75 Display|LM-75]] is a `Room` with `kind="display"`. Everything structural —
pipe walking, overlap checks, the terminal-arrowhead test — then treats it like any other box for
free, and the only work is excluding it from the tables a little man walks (`room_of`,
`nearest_out`/`nearest_in`). A 64×64 display would otherwise put 4096 dead cells in those.

## 17:15 — the bug it flushed out

First `lm check` on a display wired from below:

```
error: a pipe attaches to the right side (29,10) of the display at (24,0)
```

(29,10) is not on the display, and it is one cell past the pipe's last cell. Cause:
[[A terminal arrowhead may also be a bend]] — `Pipe.entry_dir` was derived from the last two *cells*,
which is EAST for `>----^` even though the arrowhead points north. Now recorded by `_walk_pipe` at
the moment it terminates.

Worth more than the display work: that same field is what `U` uses to decide which way to turn
([[U turns toward the pipe flow]]). Every merge of two producers we might have written would have
turned a man into a wall, and it would have looked like a mystery crash rather than a loader bug.

## 17:25 — verification against real frames

Wrote `programs/palette.man`: one room, a 63-count [[Backpack instructions|backpack]] loop that
streams 64 pixels of the current colour to DATA, then a park-and-swap to send `1` to SWAP, then
`16 - c` into `X` as the loop-or-halt branch. 34×11, 6663 ticks.

**16/16 frames, byte for byte**, against the frames the server actually ships in `palette`'s public
case. That is 1024 DATA writes and 16 SWAPs, so it exercises the [[Display cursor|cursor]] wrap every
64 pixels, the [[Display buffers|double buffer]] under `SWAP 1`, and the hex frame encoding — all
against real expected data rather than against our reading of the spec.

The timing was the interesting part of writing it. The DATA pipe is 2 cells and the SWAP pipe is 19,
so the swap for frame *n* must reach the device after frame *n*'s last pixel and before frame *n+1*'s
first: `D ≥ S + L_swap − L_data`. The layout gives 29 ticks of margin, and 4 ticks of halt corridor so
the last frame commits **before** the man stops — deliberately, so `palette` does not depend on
[[Display pipes drain after the last man halts]], which is still a guess.
