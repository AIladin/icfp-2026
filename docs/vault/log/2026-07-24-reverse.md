`reverse-a-list` — read `n` then `n` integers, print them reversed. `n ≤ 16`, 1–3 lists per case.
**Solved, 20/20 on the server**, currently **148M** and 12th. Design written up as
[[Pipe fan stack]].

## Reversing needs a stack, and only one candidate survives the pricing

A [[Pipes|pipe]] is FIFO and a [[Delay line ring]] is a queue, so two of them reverse `n` items in
`O(n²)` moves. Three ways out, priced against [[Scoring model|`max(w,h)²·ticks`]]:

| primitive | verdict |
| --- | --- |
| rotate-and-drop on a ring | latency-bound; a sparse ring pays a full lap per shuttle. Costed at ~718 avg ticks on the public set — the full-size cases kill it |
| pack a stack into a register | **dead on arithmetic**: values are 64-bit and `x` needs 21 bits, so a word holds 3 |
| **fan of addressable pipes** | built |

The ring was worth costing rather than dismissing — footprint is squared, and at ~196 it would have
been very cheap. It loses because `n = 16` rounds dominate and cost it ~1200 ticks each.

## `R`/`U` is a priority queue you build out of geometry

The first fan gave READER a matching 16-slot scan with `q` to test occupancy. That was the wrong
instinct and cost **1.9×**.

`R` and `U` take from **any** ready pipe, breaking ties in *reading order over the pipes' destination
segments* — top to bottom. That is a static priority queue, free, no decode. Fill the fan **upward
from the bottom slot** and the topmost occupied pipe always holds the value that must come out next,
so READER needs no addressing at all and an empty slot costs literally nothing.

> [!tip] `U` pays for a corner
> A cycle needs four turns. `U` reads **and** turns away from the pipe it read — every pipe is on
> READER's west face, so that is always east — and `d` turns because it is the test. Two of the four
> turns come free, which puts the drain loop at **six cells, its floor**:
> ```
>  Usdv        U = read + turn east    d = test; straight through = done
> >^m<         s = emit                m = count down
> ```

Deleting the scan also deleted the reason for pairing two values per pipe (`r M r s W s`, the most
two registers can reverse). **One value per pipe is both simpler and faster**, at the same row count.

## The ordering bug that only shows on short lists

Putting `d` *after* `m` is the obvious order and it is wrong. It needs `BP = n+1`, which needs
`M 1 +` on the entry path — three cells paid **every round**, against two ticks saved **per value**.
Net effect: `full size` improved by 55 ticks while `singletons` got *worse* by 21.

Putting `d` before `m` and starting at `BP = n-1` gets both: the last lap emits and then falls out.
That version beats the previous build on all eight public cases.

> [!warning] A per-value win can be a per-round loss
> `n ≤ 16`, so a loop body and a once-per-round entry path are within an order of magnitude of each
> other. Always re-read the **per-case** table, not the total — the total hid a regression on half
> the cases.

## The gate, and what it does for free

READER must not start early: `R` would happily drain slot 16 while slot 1 was still unwritten, which
is a **wrong answer, not a stall**. One pipe below the fan carries a go-token WRITER sends after its
last store. The token is `n` itself, so it is also READER's loop counter — which is the reason
READER never inspects a slot. B holds `n` untouched across the fill (nothing on the lane writes B),
so `W` hands it back at the gate.

Nothing gates the other direction: [[Rounds|round `N+1`'s input is withheld]] until round `N`'s
output completes, so WRITER's next `r` blocks on its own, and its walk home is free.

| build | footprint | local ticks | local score | **server** |

| 8 slots × 2 values, READER scans with `q` | 676 | 431 | 291 694 | 207M |
| 16 slots × 1 value, READER pops with `R` | 676 | 229 | 154 382 | — |
| + user's repack | 484 | 260 | 125 598 | 163M |
| + `U`, test after `m` | 484 | 255 | 123 299 | 156M |
| **+ test before `m`** | **484** | **240** | **116 039** | **148M** |

## Packing is a separate job, and it is worth about as much as the algorithm

The user repacks by hand from a sparse generated layout ([[I-O rooms belong on one side]] again:
the I/O band was five rows of pure bounding box against seven unused columns). 676 → 484 is **1.4×**
for zero instruction changes, comparable to the whole `R` rewrite. Same split as `memory`.

> [!warning] A long output pipe costs a fixed tax every round
> Running identical logic sparse (short I/O pipes, footprint 676) gives **208** average ticks; the
> 22×22 packed build gives **240**. The 32-tick gap is entirely the 14-cell output pipe wrapping
> under WRITER — [[Scoring model|ticks stop at the final output value]], so the last value of every
> round pays the full traversal. At ~2.5 rounds per case that is ~13 ticks/round, **~6% of the
> score**, and it is invisible unless you A/B the same program at two packings.

## Where the remaining headroom is, and why we should stop

Ticks are at the floor: `full size` runs 192 ticks/round against a hard **176** for 16 values
(5 writing + 6 reading each). What is left:

| lever | worth |
| --- | --- |
| output pipe adjacent to READER | ~6% |
| unroll the drain loop 2 values/lap (2×5 rectangle, 5 ticks/value, needs a parity pre-step) | ~7% |
| footprint 484 → 441 (READER's logic fits 4 interior columns, not 5) | ~9% |

All three together are ~1.25×, landing near **119M against a 99.1M leader** — so this problem cannot
be won by grinding it. And the floor is structural: 16 slots force 17 pipe rows, hence ≥19 rows of
height, while WRITER's lane + two chutes + a riser force ~21 columns.

**Nine graded problems are still untouched.** Per [[Ranking and points]] a problem is worth up to 2
points — 1 for the fraction of cases passed, 1 for rank — so passing a new problem at all beats
moving `reverse-a-list` from 12th to 5th by roughly an order of magnitude. Next is `sort-numbers`,
same Semester 1, same `lengthPrefixed` I/O shape, and the fan is directly reusable.

> [!note] `R`'s priority is static, so it does not sort
> Tie-break is by pipe *position*, not by value, so `sort-numbers` cannot reuse the pop directly —
> but the addressable fan as a 16-slot store, and the `n`-carrying gate, both port unchanged.
